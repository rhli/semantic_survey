# dbt: 语义层的服务能力与计费（官方文档 + 第三方基准）

## 摘要

汇总 dbt Semantic Layer 的服务层能力（saved queries、exports、两层缓存）与计费模型。计费按 **"Queried Metrics"** 计量是这条产品线最独特的商业设计，也是第三方吐槽消费型定价的来源。

## 要点

### saved queries：服务层的地基

把逻辑相关的指标、维度、筛选组合成一个命名查询。关键性质：**saved query 是 dbt DAG 中的节点**，在血缘中可见。可在 `dbt_project.yml` 里用 `saved-queries` 配置项目级设置，避免逐文件配。

它是另两个能力的前置条件——exports 和声明式缓存都构建在 saved query 上。

### exports：把指标物化回数仓

在 saved query 配置上追加 export，定义写出的 schema 与表名，由 dbt 的 job scheduler 调度执行为表或视图。

官方说明的意图值得记：**让指标逻辑集中在 dbt 中管理，而不是变成数仓里的一个视图**，从而保证指标值在所有接口间一致。这是给"BI 工具连不上语义层 API"场景的退路——先物化，再让可视化工具连数仓。

### 两层缓存

| 层 | 机制 |
|---|---|
| **result cache** | 借用数据平台自身内建的缓存层 |
| **declarative cache** | 用 saved query 配置**预热**缓存，需要预判要缓存哪些查询 |

声明式缓存的细节：
- 必须在 saved query 的 YAML 中**已定义 export** 才能缓存，`cache: enabled: true`。
- 运行 saved query 时，语义层从 saved query 构建缓存表写入数据平台。
- 匹配 saved query 输入的查询请求走缓存。
- **对已在 saved query 配置中的维度加筛选，仍然命中缓存**——这一条重要，意味着不必为每个筛选组合单独建缓存。
- **检测到相关上游模型有新鲜数据时自动失效**，下次运行 saved query 时刷新或重建。

数据驻留上的关键事实：缓存**使用客户自己数仓的存储**，不存在 dbt Labs 系统上；客户数仓数据不在 dbt Labs 持久保留（可能临时性 ephemeral 缓存）；且缓存是客户 opt-in。

### 消费接口

CLI、GraphQL API、JDBC、Python SDK，以及 **dbt MCP server**（配置需要 PAT 或 service token + dbt 生产环境 ID）。托管 BI 集成含 Tableau、Excel、Hex、Mode（官方有对应的查询 mini-course）。

### 计费：Queried Metrics

- 用量以 **distinct "Queried Metrics"** 计量：**每次成功的 compute/render 请求按请求中的指标数计数**。
- **元数据调用不计费**；**开发环境（IDE）运行不计费**。
- 另一个计费维度是 Successful Models Built（scheduler、CI、API 触发的部署环境运行），按模型逐个计——100 个模型的作业在第 51 个失败，计 51 个。test、seed、ephemeral model、snapshot 不计。

档位与额度：

| 档 | 价格 | 额度 |
|---|---|---|
| Developer | 免费 | 1 seat、1 project、3,000 models/月（超出作业暂停） |
| Starter | $100/user/月 | 最多 5 seats、15,000 models/月、**5,000 queried metrics/月**、1 project |
| Business | 约 $1,200/developer/月（第三方基准，非官方标价） | SSO、RBAC、审计日志、高级 CI、语义层 |
| Enterprise | 议价 | 100,000 models/月、**20,000 queried metrics/月**、30 projects |
| Enterprise+ | 议价 | 不限 project + PrivateLink / IP 限制 |

**缓存与多凭证需要 Enterprise / Enterprise+**。声明式缓存另有前置条件：环境必须在 release track 上（不能是 legacy dbt Core 版本）、需要成功的作业运行与生产环境。

## 关联

- [[dbt Semantic Layer]] 产品页的服务层与商业模式部分。
- "queried metrics" 计费与 [[Cube]] 的自托管、[[Unity Catalog]] 的平台内建（无独立语义层计费）构成商业模式的三种形态，是 [[Headless BI]] 概念页的实证材料。
- declarative cache 的"对 saved query 内已有维度加筛选仍命中缓存"与 Databricks 物化的 rollup match 是同类问题的不同解法，可对比 [[Query Acceleration]]。
- **口径冲突待核实**：官方 FAQ 称"dbt Starter、Enterprise 或 Enterprise+ 客户可访问语义层"，未提 Business；第三方基准报告（vendorbenchmark.com）称"语义层包含在 Business 和 Enterprise 档，不含 Team"。两处对档位命名与包含关系的表述不一致，且"Team"档在官方当前定价页未出现，疑为旧档位名。以官方 FAQ 为准，第三方数字仅作参考。
- 价格数据为 accessed 日期口径，定价页变动频繁，引用前需重新核对。
