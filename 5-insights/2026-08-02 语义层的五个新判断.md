# 语义层的五个新判断（2026-08-02）

本轮扩容调研（Google/Microsoft/Salesforce 入库，Tier 1 全部深填）后，五个值得记住的判断：

## 1. "双层架构"成为大厂共识：指标语义 + 本体上下文

Databricks（Metric Views + [[Genie Ontology]]）、Microsoft（semantic models + Fabric Ontology）、Google（LookML + Knowledge Catalog）三家不约而同走向同一结构：**一层治理指标定义，一层自动构建实体/关系上下文**。Snowflake 是唯一押注单层的大厂（语义视图 + Autopilot 包打）。判断：双层会赢——指标定义的精度要求与上下文覆盖的广度要求本质冲突，一层做不好两件事。

## 2. Grounding 必须编译进语义工件，prompt 补丁不可靠

微软把这条写成了显式架构约束：Fabric Data Agent 的 DAX 生成工具**只读模型元数据与 Prep for AI 配置，忽略 agent 级指令**。这是全行业最诚实的一句话。推论：评估任何 ChatBI/Agent 产品，先问"语义供给落在哪个工件里"，答"prompt/指令层"的直接打折。

## 3. Verified examples 三件套成为事实标准

Snowflake（verified queries）、Microsoft（verified answers）、Looker（golden queries）——三家独立收敛到同一机制：**人工确认的问题-答案对，既引导生成又充当评测 ground truth**。Snowflake 更进一步把评测做成产品功能（`sql_correctness` 回归检测）。这是"语义建模如何量化评测"目前最工程化的答案。

## 4. "开放"有三种含义，别被话术混用

- **引擎开源**：MetricFlow、Cube Core（实现可审计、可自托管）
- **语言开源**：AtScale SML（模型可移植，引擎闭源）
- **标准开放**：OSI/Apache Ossie（定义可交换，各家实现各自闭源）

AtScale 的 "open semantics" 是第二种，Snowflake 推的是第三种，dbt 是第一种。**三者解决不同的锁定问题**，评估厂商开放性时先分清在说哪一种。

## 5. 平台互操作出现首个实信号，但微软缺席 OSI 是最大变数

LookML 新增 in-database 模型支持，可叠加在 [[Snowflake Semantic Views]] 之上消费——平台语义层之间第一次有了真实的（非纸面的）互操作。同时 OSI 进入 Apache 孵化器更名 Ossie、治理中立化，50+ 成员里**没有微软**。语义层世界正在分裂成"OSI 阵营"与"微软闭环"，这个分岔比任何单一产品竞争都更决定行业走向。
