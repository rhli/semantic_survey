# dbt: 语义模型与指标规范（官方文档）

## 摘要

MetricFlow 语义模型与指标的官方规范。**规范本身正在换代**：新版（dbt Core 1.12+）把 `semantic_model` 内联到 `models:` 下，且用 simple metric 取代了独立的 `measures`。网上大量教程用的是旧规范，引用时需注意版本。

## 要点

### 三类构件

**Entity（实体）**——数据的粒度标识，也是 join 的依据。四种类型：

| 类型 | 语义 |
|---|---|
| `primary` | 每行一条记录，且包含数据平台中的全部记录 |
| `unique` | 每行一条记录，但可能只是全体的子集，允许 null |
| `foreign` | 同一记录可以有零条、一条或多条实例，允许 null |
| `natural` | 基于真实世界数据唯一标识记录的列或列组合（如 `sales_person_id`） |

`primary` 与 `unique` 的区别（是否覆盖全体）是 MetricFlow 决定 join 语义的依据，比一般理解的"主键"更细。

**Dimension（维度）**——指标的 group by 参数。分 `categorical` 与 `time` 两类，time 维度带 `type_params.time_granularity`。

**Metric（指标）**——五种类型：

| 类型 | 关键属性 |
|---|---|
| `simple` | `agg`、`expr`、`time_granularity`、`agg_time_dimension`、`join_to_timespine`、`fill_nulls_with`；可选 `non_additive_dimension` |
| `ratio` | `numerator`、`denominator`（各可为指标名或含 `name`/`filter`/`alias` 的字典） |
| `derived` | `expr`、`input_metrics`（每个可带 `alias`、`filter`、`offset_window`） |
| `cumulative` | `input_metric`、`window`、`grain_to_date`、`period_agg` |
| `conversion` | `entity`、`calculation`、`base_metric`、`conversion_metric`、`window`；可选 `constant_properties` |

全类型通用属性：`name`、`type`、`description`、`label`、`hidden`、`filter`、`config`（支持 `meta`、`group`、`tags`、`enabled`）。

`conversion` 是漏斗分析类型（如 view-to-purchase），`constant_properties` 用于确保两个事件在某维度上取值相同。`non_additive_dimension` 处理半可加度量（如期末余额）。

### 规范换代

**新版（dbt Core 1.12+）**——`semantic_model` 内联在 model 下，`metrics` 是与 `semantic_model`、`columns` 并列的顶层列表（**不嵌套在 `semantic_model` 里**），类型参数提到每个 metric 的顶层：

```yaml
models:
  - name: orders
    semantic_model:
      enabled: true
    metrics:
      - name: order_count
        type: simple
        agg: count
        expr: 1
      - name: conversion_rate
        type: ratio
        numerator: orders
        denominator: sessions
```

**旧版**——顶层 `semantic_models:` 块，独立的 `measures:` 列表，指标通过 `type_params` 引用 measure：

```yaml
semantic_models:
  - name: transactions
    model: ref('fact_transactions')
    defaults:
      agg_time_dimension: transaction_date
    entities:
      - name: transaction
        type: primary
        expr: transaction_id
      - name: customer
        type: foreign
        expr: customer_id
    dimensions:
      - name: transaction_date
        type: time
        type_params:
          time_granularity: day
      - name: transaction_location
        type: categorical
        expr: order_country
    measures:
      - name: transaction_total
        agg: sum

metrics:
  - name: revenue
    type: simple
    type_params:
      measure: transaction_total
  - name: sales_minus_revenue
    type: derived
    type_params:
      expr: sales - revenue
      metrics:
        - sales
        - revenue
```

两个变化的实质：（1）语义定义与 dbt model 从"并列的两个文件"变成"同一个 model 的一个 section"，进一步贴合 metrics-as-code；（2）`measures` 这个中间概念被消解——simple metric 直接带 `agg` 与 `expr`，少一层间接。

### 其他

- 一个 dbt model 可以定义多个语义模型。
- **dbt Wizard 可以生成语义模型**，在 dbt 平台或本地 CLI 均可。
- dbt Labs 另发布了 agent skills 仓库（`dbt-labs/dbt-agent-skills`），含 `building-dbt-semantic-layer` skill，即用 agent 辅助语义建模已是官方支持路径。
- 维度对 SCD（缓慢变化维）的支持文档标注"目前存在限制"。

## 关联

- [[dbt Semantic Layer]] 产品页的语义表达力部分主要依据本文档。
- 指标类型的丰富度（尤其 `conversion`、`cumulative` 的 `grain_to_date`/`period_agg`）是与 [[Unity Catalog]] Metric Views（measures + 实验性 window 块）、[[Snowflake Semantic Views]] 对比的关键差异点。
- `entity` 四类型 + 自动 join 路径选择，与 Databricks 要求预先声明 join、并靠 `rely` 声明基数的做法形成对照。
- 规范换代这件事本身值得记：意味着 2026 年前的 dbt 语义层教材大面积过时。
